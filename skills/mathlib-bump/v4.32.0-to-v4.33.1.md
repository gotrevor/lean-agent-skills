# mathlib v4.32.0 → v4.33.1 - breaking-change cookbook

*[ Claude wrote all of this.  I think it's good stuff - but, treat with care! -Trevor ]*

Started 2026-08-22 from the Lean 4.33.0 release notes, a mechanical diff of the two Mathlib tags,
and three fleet ports. Evidence labels as in the sibling catalogs:

- **Lean release note** - an upstream-declared change, not necessarily hit downstream yet.
- **Tag diff** - derived mechanically from the v4.32.0 and v4.33.1 Mathlib sources. Not a guess, but
  also not proof that anyone trips over it.
- **Fleet port** - hit in one of *our* ports, with the exact error text. Held to the highest standard.

**v4.33.1 is a patch release** (ThreadSanitizer support, `lean_dec_ref_cold` codegen). Nothing in it
breaks source. The whole substantive step in this window is **v4.33.0**, and everything below is
about that; the `.1` is simply the newest stable tag Mathlib has published, so it is the right pin.

## The shape of this window

Two rename populations, and only one of them is dangerous:

| | Count | Symptom | Cost |
|---|---|---|---|
| **Newly `@[deprecated]` aliases** | ~250 | warning that **names its own replacement** | trivial - unless the project sets `weak.warningAsError`, where it is a hard error |
| **Aliases DELETED outright** | **303** | bare `Unknown identifier`, nothing to grep | the entire cost of this bump |

Mathlib carried 1959 `alias` declarations at v4.32.0; 303 of them are simply gone at v4.33.1, with
no `@[deprecated]` tombstone. That is the class this catalog exists for. The full generated mapping
is in [`v4.32.0-to-v4.33.1-deleted-aliases.tsv`](v4.32.0-to-v4.33.1-deleted-aliases.tsv) - 271 of
the 303 resolve to what the alias pointed at in v4.32.0, which is the mechanical substitution.

## First-response checklist

1. Pin the pair exactly: `leanprover/lean4:v4.33.1` and Mathlib `v4.33.1`.
2. Regenerate `lake-manifest.json`, fetch the cache, then `lake build` **every configured library**,
   not just `defaultTargets`.
3. On any `Unknown identifier`, **look it up in the TSV before rewriting the proof.** Most are a
   one-token substitution, and several are traps (see A).
4. On `unsolved goals` / `made no progress` with no rename involved, suspect the transparency
   change (B) before anything else, and use its escape hatch as a diagnostic.
5. Re-pin the satellites (docbuild sub-project, CI's `lean4export` tag). `lake build` reads none of them.
6. Compare `#print axioms` on the headlines against the pre-bump baseline. Green is not faithful.

# Part 1 - Mathlib

## A. 🚨 `mul_le_mul_left'` and `mul_le_mul_right'` are deleted, and the replacement is CROSSED

**Evidence:** Fleet port (erdos-880, 9 sites); tag diff.

```
error: src/Erdos880/Thm10.lean:965:35: Unknown identifier `mul_le_mul_right'`
```

No deprecation warning, because the *alias line itself* was removed. In
`Mathlib/Algebra/Order/Monoid/Unbundled/Basic.lean`, v4.32.0 had:

```lean
theorem mul_le_mul_right [MulLeftMono α]  (bc : b ≤ c) (a : α) : a * b ≤ a * c   -- line 70
alias mul_le_mul_left'  := mul_le_mul_right                                      -- line 74
theorem mul_le_mul_left  [MulRightMono α] (bc : b ≤ c) (a : α) : b * a ≤ c * a   -- line 81
alias mul_le_mul_right' := mul_le_mul_left                                       -- line 85
```

v4.33.1 keeps **both theorems, unchanged, under the same names** and deletes **only lines 74 and 85**.

So the migration is:

| Removed | Use instead | Which side it multiplies |
|---|---|---|
| `mul_le_mul_right'` | **`mul_le_mul_left`** | right: `b * a ≤ c * a` |
| `mul_le_mul_left'` | **`mul_le_mul_right`** | left: `a * b ≤ a * c` |

**The obvious fix is the wrong one.** Dropping the prime - `mul_le_mul_right'` → `mul_le_mul_right`
- silently selects the *other* lemma. In a commutative setting it may even go on to typecheck
somewhere downstream. The unprimed names have always been "which side the *multiplier* sits on";
the primed aliases were named the opposite way, and deleting them exposed the inversion.

⚠️ **`le_of_mul_le_mul_right'` and `le_of_mul_le_mul_left'` still exist in v4.33.1** and are *not*
crossed. A blind `sed s/mul_le_mul_right'/mul_le_mul_left/` corrupts them. Use a negative lookbehind:

```python
re.compile(r"(?<!le_of_)\bmul_le_mul_right'")
```

This pair is the single most-used deletion in the window: 44 uses of `mul_le_mul_left'` and 41 of
`mul_le_mul_right'` across the Reservoir mirror, spread over **20 distinct packages**.

## C. Family sweeps behind the deletions

**Evidence:** Tag diff.

Three recurring shapes account for most of the 303. Recognising the family is faster than looking up
each name:

- **`Splits.*` namespacing** - polynomial splitting lemmas moved under the `Splits` namespace and
  often shed a `_of_splits` suffix: `natDegree_eq_card_roots → Splits.natDegree_eq_card_roots`
  (59 ecosystem uses), `roots_map → Splits.map_roots`, `adjoin_rootSet_eq_range`, `image_rootSet`.
- **`coe_*` → `natCast_*` / `FunLike.coe_*`** - the cast-normalisation wave. Mostly landed as proper
  deprecations (so, warnings), but a handful were deleted: `coeFn_sum → coe_sum`.
- **`restrict` → `domRestrict`** - `AddHom.restrict`, `AlgHom.restrictDomain`, `codRestrict_restrict`.

## D. Deprecations that are *not* new here

**Evidence:** Tag diff. Correcting an easy misattribution.

The `Set.*_diff → Set.*_sdiff` family (`Set.image_diff`, `Set.mem_diff`, `Set.Infinite.diff`, the
`ncard_diff`/`encard_diff` cluster) carries `@[deprecated (since := "2026-06-03")]` and is **already
present in v4.32.0**. If these warnings appear during your v4.33 bump they were firing before it -
do not file them against this window. Same for `push_neg → push Not`, which belongs to v4.31 → v4.32.

Genuinely new in this window: `ENat.coe_lt_top → ENat.natCast_lt_top` (absent from v4.32.0, present
in v4.33.1) and its ~250 siblings in the cast wave.

# Part 2 - Lean 4.33.0 core

## E. `backward.isDefEq.respectTransparency.types` is now on by default

**Evidence:** Lean release note.

The one no-rename behaviour change, and the likeliest source of an `unsolved goals` or
`made no progress` that has nothing to grep for. A metavariable assigned at reducible, instances, or
implicit transparency now has its type compared with its value's type at **implicit** rather than
default transparency.

**Use the switch as a diagnostic first**, over the smallest declaration that fails:

```lean
set_option backward.isDefEq.respectTransparency.types false in
```

If that alone compiles it, the transparency tightening is your cause. The intended fix is to mark the
definitions involved `@[implicit_reducible]`, not to leave a project-wide compatibility switch
sitting there uncommented. `set_option linter.tacticCheckInstances true` helps localise it.

This is the same category as the v4.29.1 → v4.31.0 window's largest section - if that catalog's
transparency entries are familiar, read them alongside this one.

## F. `Nat.ne_of_gt` is now `protected`

**Evidence:** Lean release note; confirmed against both toolchains.

The same file and line in each release, having gained one keyword:

```lean
-- v4.32.0  Init/Data/Nat/Basic.lean:441
theorem ne_of_gt {a b : Nat} (h : b < a) : a ≠ b := (ne_of_lt h).symm
-- v4.33.1  Init/Data/Nat/Basic.lean:441
protected theorem ne_of_gt {a b : Nat} (h : b < a) : a ≠ b := (ne_of_lt h).symm
```

So under `open Nat`, an unqualified use that resolved in v4.32.0 now does not:

```
error: Unknown identifier `ne_of_gt`
```

Qualify it as `Nat.ne_of_gt`, or reach for the general order lemma. The error names the identifier
but gives no hint that `protected` is why it stopped resolving - which is what puts it in this
catalog rather than in the release notes alone.

## G. Namespace moves into internal namespaces

**Evidence:** Lean release note.

- `Int.Linear` → `Int.Internal.Linear`
- `IO.AsyncList` → `Lean.AsyncList`
- `LLVM` → `Lean.LLVM`

Metaprogramming and tactic-authoring code only; ordinary mathematics will not notice.

## H. Kernel deep recursion is now deterministic

**Evidence:** Lean release note.

`(kernel) deep recursion detected` no longer depends on stack luck. A proof that was quietly near the
limit can start failing reproducibly. Bump `set_option maxRecDepth` for the affected declaration -
and treat a *new* one as a signal that the declaration is doing more kernel work than you think,
especially anything `decide`-shaped.

## I. `Float.lt` and `Float.le` return `Bool`, not `Prop`

**Evidence:** Lean release note.

The `LE`/`LT` instances are unaffected, so `≤`/`<` notation is fine. Only direct calls to
`Float.lt` / `Float.le` break.

## J. `bv_decide` and the BitVec simp sets

**Evidence:** Lean release note.

`bv_decide` now uses `ext_iff` lemmas for structure equality and otherwise does not reason about it,
so your structures may need `@[ext]` or a hand-written extensionality lemma. Separately,
`int_toBitVec` splits into a `SymM` and a `MetaM` simp set - existing users want `int_toBitVec_meta`.

## K. Lake

**Evidence:** Lean release note.

The `setup` facet is no longer buildable from the CLI. A new `requiresModuleSystem` option warns when
non-module files import the package.

# Part 3 - Which deletions actually bite

**Evidence:** Tag diff + a scan of the ~700-package Reservoir mirror.

Occurrence counts for the removed aliases, word-boundary matched. ⚠️ The mirror's packages are pinned
at many different Mathlib versions, so a count is **"will break when this package bumps"**, not "is
broken today."

| Removed alias | Replacement | Uses |
|---|---|---|
| `add_lt_add` | `add_lt_add_of_lt_of_lt` | 459 |
| `natDegree_eq_card_roots` | `Splits.natDegree_eq_card_roots` | 59 |
| `isMultiplyPretransitive` | `alternatingGroup.isMultiplyPretransitive` | 54 |
| `mul_le_mul_left'` | `mul_le_mul_right` ⚠️ crossed | 44 |
| `mul_le_mul_right'` | `mul_le_mul_left` ⚠️ crossed | 41 |
| `isFinitelyPresentable` | see TSV | 37 |
| `lex_lt_iff` | `Lex.lt_iff` | 27 |
| `isTrivialBlock_of_isBlock` | see TSV | 27 |
| `filter_card_add_filter_neg_card_eq_card` | see TSV | 26 |
| `roots_map` | `Splits.map_roots` | 17 |
| `degree_def` | `degree_apply` | 14 |
| `left_mem_Ici` | `self_mem_Ici` | 12 |
| `coeFn_sum` | `coe_sum` | 10 |

`add_lt_add → add_lt_add_of_lt_of_lt` is the highest-volume deletion in the window by a wide margin
and deserves checking first in any analysis-heavy project.

# Fleet ledger

Three ports, v4.32.0 → v4.33.1, all axiom-gated (`#print axioms` on the headlines compared before and
after; footprints required to be unchanged).

| Repo | Source changes | Notes |
|---|---|---|
| `binomial-thresholds` | **0** | version files only. Both headlines unchanged at `[propext, Classical.choice, Quot.sound]`. |
| `inverse-galois` | **0** | version files only. Its own `#assert_canonical_axioms` elaborator throws on non-canonical axioms and is imported by the root module, so the green build *is* the gate. |
| `erdos-880` | **9**, all entry A | `Construction` (7), `Thm9` (1), `Thm10` (1). All five headlines unchanged at the standard triple. |

Two of three needed no source change at all. For a mathlib-only project this window is narrow - the
risk is concentrated almost entirely in the 303 deletions, and a project that happens to use none of
them will sail through.
